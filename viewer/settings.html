Attendees who open the phone view see the welcome screen until you press Start event on the status page, and again after End event. The words sit on a dark panel over the image, so any photo keeps them readable. JPEG, PNG, or WebP, up to 5 MB. The logo sits in a slim row above the captions while they are live — a transparent PNG works best, since readers choose their own background colour. Give it a description so screen readers announce the name, not the file. The disclaimer appears once per device the first time someone opens the phone view, with a dismiss button — it reappears if you change the wording, but not just because you saved the field again.

Get a key: portal.azure.com → Create a resource → search “Translator” → Create (a free tier is available) → once it deploys, open the resource → Keys and Endpoint → copy Key 1 and the Region. Paste the key above, list the languages to translate into, then Save — no restart needed.

One-time setup: at one.dash.cloudflare.com → Networks → Tunnels → Create a tunnel → Cloudflared → name it → add a Public Hostname pointing this event's subdomain at HTTP  localhost:8000 → copy the token shown in the install command. Paste the hostname and token above, then Enable — no restart needed. Needs the domain on Cloudflare's DNS and cloudflared installed (brew install cloudflared) — see SETUP.md 3c.

In ProPresenter: Settings → Network → Enable Network, and note the port. Stage message needs a stage layout with a Stage Message element on the screen that should show captions. Message needs a Message with the name above and one text token with the token name above — you design its look in ProPresenter; nothing else in the library is touched. Keep the Web Fill prop (wall URL) as the fallback. See SETUP.md 7a.
One key per output. While any key exists, a wall URL without a valid ?key= is refused, so revoking a key switches that output off without editing every scene and prop. With no keys, the plain wall URL works for everyone, as before. The tuner builds URLs with the key included. Phones are never affected.
Boosted vocabulary (config/keyterms.txt) and words to strip out of every caption (config/blocklist.txt) are both plain text files, one term or short phrase per line — edit either by hand, then press Reload. Blocking works the same way on every backend; the profanity filter below catches common strong language with no list to maintain.
